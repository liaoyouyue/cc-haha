# CCHH Mobile 0.2｜产品设计基线 PRD（Android）

状态：**设计稿 / 待实现 / 待真机验证**  
日期：2026-10-21 · 源码基线 `dae2852bb975c3b2b5a70494f4e1ba860968a041` · 对标 CCHH 桌面 **0.7.4**（实际安装版本仍须复核）。  
这不是验收报告。保留原有 v0.1.5 APK 与 Draft PR #3，禁止直接替换生产桌面程序。

## 0. 产品目标

**一部安卓手机，安全接管自己电脑上正在运行的 CCHH。** 打开聊天，看到 AI 真实正在做什么，可靠地发送下一步指令、审批、查看文件与结果；离开 Wi-Fi 后仍可通过用户自行选择的免费网络方式连接。群友使用同一个 APK、各自配对各自的电脑，没有开发者共享账户、公共中转必需服务或绑卡要求。

不是：社交/社区聊天 APP、远程向别人发消息的工具、内置 AI API 收费平台、伪装成“全功能远程桌面”的信息页面，也不复制第三方 APP 标志/代码。

优先级：**体验质量 > 标签数量；真实功能 > 宣传文案；不重复执行 > 自动重试速度。**

## 2. 核心体验与页面流程

### 2.1 正常打开

`启动 → 本机安全凭据恢复 → 主机连通/授权检查 → 最近使用的会话 → 聊天`。  
不再每次回到一个占满屏幕的“选择连接方法”表单。未配对时显示极简的“连接我的 CCHH”向导；失效时展示“重连 / 重配对 / 离线只读”可区分状态。

顶部左侧：圆形 CCHH 头像 / 切换电脑；中间：CCHH Mobile + 会话名/连接状态；右侧：历史会话入口。**不照抄 Loopii 的品牌和图标资源。**

### 2.2 聊天主页面（P0，必须认真做）

布局结构（安卓安全区内，自上而下）：

```text
┌────────────────────────────┐
│  C    CCHH Mobile       ◷  │  ← 切电脑 / 历史
│      项目A · 已连接          │
├────────────────────────────┤
│  [今天]                    │
│  你：帮我检查这次提交       │
│                            │
│  CCHH                      │
│  思考 00:26 · 正在执行       │  ← 只按真实事件呈现
│  ▸ Read: src/...            │  ← 工具调用可展开
│  ▸ Bash: npm test           │
│  结果 Markdown / 代码块     │
│                            │
├────────────────────────────┤
│  消息队列 · 1 条         ↑ ×│  ← 草稿/待发，状态明确
│  [deepseek...  ⌄] [思考 ⌄]  │
│  ＋  发消息…           ■/↑  │
├────────────────────────────┤
│  聊天  任务  终端 文件 桌面 │  ← 最终产品导航目标
└────────────────────────────┘
```

**消息类型定义：**

- User：与服务器确认的消息、发送中、未确认、发送失败；不能用纯时间戳推断成功。
- Assistant：段落、标题、列表、行内代码、带复制按钮的代码块、引用；按消息 ID 合并流式增量，不闪烁、不滚跳。
- Thought：仅在协议提供合法的 thinking/reasoning 事件或内容时展示“思考”；没有数据时只写“正在执行”，**不伪造思考过程**。等待计时标注“本次执行已等待”，不误导为模型实际推理时长。
- Tool：工具名称、输入摘要、执行中/完成/失败、耗时、可展开结果、敏感内容默认折叠。
- Permission：工具、工作目录、风险提示、参数预览、本次批准/拒绝；决策一次性提交并匹配 requestId。
- Error/Disconnect：就地展示“服务器断开 / 等待恢复 / 可能已执行”，不清空已显示内容；不能自动重复最后一次写操作。

**输入区：** 48dp 最小可点击区域，随安卓键盘上移，长文本最大高度约 35% 屏高；底部导航随键盘隐藏或合理压缩，发送键不被遮挡。停止按钮在执行中出现；新消息与当前执行并存时支持“存为待发”，但除非已核实服务端队列/幂等确认，不自动发出。

**队列：** 以 `hostId+sessionId` 隔离，持久化**未发送草稿**到设备存储（草稿正文可能敏感，应进行私有存储/清理）；支持新增、编辑、重排、取消、逐条手动发送。网络不确定情况下不自动重放 `user_message`；恢复历史后用户明确确认是否重发。队列 UI 必须清楚说明“待发 ≠ 服务端已排队”。

**模型/思考：** 显示电脑实际返回的值及来源，修改前弹出“将更改电脑默认设置”的确认。未经服务端会话级接口证实，不叫“会话专属模型”。请求失败必须保留旧值并给出错误解释。

### 2.3 任务（P1）

价值：手机一眼知道“AI 在哪里、是否等我批准、完成了吗”。优先展示：
- 当前会话活动状态及每次执行开始/结束时间；
- 待审批操作排在最上方；
- 来自 CCHH task list 的真实任务（待办/进行中/已完成/失败），以及关联来源；
- 最近工具调用与失败原因；
- 无 task list 时用明确空状态，而不是把每条聊天消息冒充正式任务。

可点击任务进入详情：来源、执行步骤、工具输出与对应消息；无数据时不要推断进度百分比。

### 2.4 终端（最终目标 P2）

目标是**真正可用的安全项目终端**。区分两层：
- P0/P1：展示实际工具调用和真实输出，标签应为“执行记录”，**不得标成可交互终端**。
- P2：在专门设计并隔离验证的 CCHH PTY/命令通道、审计日志、路径授权和用户逐次确认就绪后，才启用“终端”：发送命令、读取输出、取消、断线恢复。默认只读，绝不为补齐标签暴露任意执行 API。

没有 P2 真实能力前：**不把“终端”空壳作为五个已完成页面的一部分**；可以用“执行记录”呈现真实信息，并在功能说明明确范围。

### 2.5 文件（P1）

从当前会话工作目录进入，显示面包屑、目录树、搜索、文件文本预览、图片预览、复制路径；受限文件类型显示原因。目录翻页和大文件按需加载。
- P1：只读文件浏览 + 真实内容预览 + 更改文件的 Diff/Git 状态（已有对应受限 session/workspace API，须先验证 H5 权限与格式）。
- P2：受控编辑/保存须逐文件授权、保护 symlink/目录穿越、冲突检查；不实现未经验证的通用写接口。

切换电脑或会话应清除旧文件树与错误数据，路径边界在**服务端** enforce，客户端防越界仅作二次保护。

### 2.6 桌面（最终目标 P3）

用户想要的是电脑桌面**实际画面和操作能力**，不是“服务在线”卡片。真正桌面功能需要经过授权的屏幕捕获、带宽控制、认证/授权、画面通道、输入控制、失联处理及隐私提示，可能超出原 CCHH v0.7.4 的 H5 API。

在 P3 能力尚未开发并验收前，电脑连接与健康状态应收纳到**主机详情/设置**，不要用“桌面”空壳充数；导航最终是否保留 5 栏以实际能力为准。

### 2.7 会话与主机

- 历史：当前主机下搜索项目/会话、最近使用排序、刷新、继续已有会话；创建/重命名等操作先核验协议。
- 主机：连接方式、可信地址、在线/重连状态、解除绑定；两台主机信息严禁混用。主机切换先终止旧 WS、清理审批、草稿作用域及历史，再加载新主机。
- 扫码：支持官方 0.7.4 LAN H5 QR，以及独立的公网 /remote#pair= 协议；二者令牌绝不能混用。用户明确确认地址，公网 HTTPS，不允许裸露服务端口直接公网暴露。
- 免费：LAN 默认；Tailscale 为用户自己的免费个人私网（受供应商政策和额度限制）；ngrok 免费档实验性、限额和账户条件变化时提示。不能要求开发者提供公共付费中转或账号。

## 3. 设计系统（视觉与动效）

保留“白底、留白、大文字、淡紫点缀”的观感，不使用 Loopii 商标/独特版权图像。
- 背景 `#FFFFFF`；一级文字 `#18171B`；次级文字 `#76717C`；分割线 `#ECEAF0`；淡紫背景 `#F5F1FB`；主强调 `#9C86C9`。错误色仅用于失败，成功色用于真实成功。
- 安卓主要基准宽 360–430dp，设计宽 393dp；系统字体优先，文字正文 16sp/行高 25–27sp；控制标签 12–14sp；顶部标题约 25–27sp；最小触控目标 48dp。
- 消息展示宽度尽量充分，AI 回复默认无笨重气泡；用户文本采用轻微区分；工具卡片淡灰边框、折叠展开。
- 顶部和底部兼容系统刘海、安全区、全面屏手势条；键盘不会压住文本输入/发送按钮。
- 明确六态：初始化、无会话、连接中、工作中、待审批、离线/错误；不得出现纯空白页、死按钮、没有反馈的图标。
- 100 条以上聊天虚拟列表保持稳定，长代码横向滚动，不意外跳到底；最新消息有浮动“跳至底部”。
- 禁止堆砌大面积装饰渐变、假图标、大块商业宣传文案、夸张动画。

## 4. 验收用的真实场景（每一项都要证明）

A. 首次配对：新装 APP → 扫本人电脑二维码 → 核对地址 → 选择现有会话 → 发一句话 → 收到实时回答 → 回看服务端历史。

B. 长任务：AI 连续工作 10 分钟以上，手机显示状态和真实工具执行内容；切换页面、切到后台再回来不重复指令、不丢历史。

C. 审批：发起一次有害性为零的工具调用 → 手机显示确切命令与目标 → 拒绝、批准分别测试 → 服务器只接受一次决策，不能通过 UI 重复批准。

D. 断网：发送状态为“未确认”时切 Wi-Fi/移动数据、锁屏、杀进程，恢复后历史对账；在证据不足时要求手动确认，不自动重发。

E. 多用户：手机 A/电脑 A 与手机 B/电脑 B 使用同一安装包、各自的凭据，绝无会话/文件/审批串线。

F. 键盘：窄屏手机、全面屏手势、输入 300 字、长按复制代码、打开选择器、工具卡片展开，都不遮挡发送键或产生布局闪动。

G. 群发门槛：固定 Beta 签名可从上一版覆盖升级、许可证与完整第三方声明可访问、真实多机记录齐全，才允许称“群友可用”。

## 6. 当前事实与尚未确认

既有 CCHH Mobile v0.1.5 有基础 LAN/ngrok 连接、会话、聊天、审批、重连；PR #3 曾通过构建与模拟器，但**并未证明视觉达到参考图质量或真机/全功能验收**。
当前主界面约 800+ 行集中在 `cchh-mobile-android/App.js`，仅用最简单的文字消息处理；已有“终端”只读工具历史、“桌面”仅健康状态、文件页无真实普通文件内容预览，都是产品缺陷而非已完成需求。

Web / 旧 PR / 文档只能证明仓库存在相关 API；**不能证明用户运行的 0.7.4 实例允许每个 H5/mobile 请求。** 此项必须使用隔离服务端验证并记录响应/字段（不上传用户令牌）。模型与 Effort 当前是桌面侧设置，优先显示真实值，写操作另做授权验证。

## 7. 不变的安全与交付边界

- 只在隔离新分支推进；保留 PR #2、#3 和用户现装 APK；不合并、不部署，不接触 CCHH 生产、FreeLLMAPI 3001、WAL/SHM、真实密钥或私有补丁。
